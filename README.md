# HSK Practice

Mobile-first PWA-shaped SvelteKit app for HSK 1–5 vocabulary and sentence practice.
Static frontend, optional PocketBase backend, client-side speech.

## Running it

```bash
npm install
npm run dev
```

`static/data/` is already generated and committed, so it runs with no other setup.
PocketBase is optional — without it, progress saves to localStorage.

To rebuild the data (after editing categories, or to change level coverage):

```bash
pip install jieba opencc-python-reimplemented
# unzip your source data to ./raw/"hsk data"/
npm run data
```

## What's in `static/data`

Generated by `scripts/build_data.py` from the HSK CSVs and the Tatoeba TSV.

| File             | Contents                                          |
| ---------------- | ------------------------------------------------- |
| `vocab.json`     | 2,595 words: `{w, p, d, l, t, c}` — word, pinyin, definition, HSK level, category tags, class chapter refs |
| `sentences.json` | 13,177 sentences + a word → sentence index         |
| `meta.json`      | level counts, category list, class chapter structure |
| `gaps.json`      | 134 words with no usable sentence                  |

Around 450 KB gzipped in total.

The build does four things worth knowing about:

1. **Traditional → Simplified.** 45% of the source sentences were Traditional.
   Everything is normalised with OpenCC before indexing.
2. **Token decomposition.** jieba merges 一百 into one token, which used to hide
   百 entirely. Unmatched tokens are split back into HSK words where possible.
3. **Substring rescue.** 160 words that segmentation still missed are found by
   direct substring match.
4. **Sentence filtering.** 4–24 characters, no Latin or digits, at most one
   out-of-list word.

Resulting coverage: HSK 1–3 at 99%+ with at least one sentence, HSK 4 at 98%,
HSK 5 at 91%, class words at 99%.

## Class vocabulary

`scripts/class/year_1.txt` and `year_2.txt` hold the class lists
(`Lesson,Chinese,Pinyin,English`). Drop in `year_3.txt` and re-run the build —
the year number comes from the filename and chapters come from the Lesson
column, so nothing else needs changing.

Of 274 class words, 172 are already in HSK 1–5 and 102 are not. Both end up in
the same `vocab.json`:

- A word in both keeps its HSK level and gains a `c` entry like `["1-5"]`.
  It shows as **HSK 1 · Y2 C12** on the card.
- A word only taught in class gets `l: 0` and shows as **Class only · Y1 C4**.
  Most of these are single characters like 睛 and 蕉 that are bound morphemes
  rather than standalone words.
- Where a word is in both lists, the HSK pinyin and gloss win, so the app stays
  internally consistent. The class chapter reference is kept either way.

Class words are also run through the normal category tagger, so picking
**Food** includes class food words. That's the one direction the axes mix.

Selecting a chapter is exclusive: it clears the HSK and category filters, and
picking a level or category clears the chapter selection. Chapters hold 7–17
words, so intersecting them with anything else would usually leave nothing.
Within the class axis you can still multi-select — several chapters, or a whole
year at once.

## Categories

`scripts/categories.json` drives tagging. Each category has `seeds` (explicit
Chinese words, always tagged) and `en` (regex patterns matched against the
English definition). Edit it and re-run the build.

**This currently tags 31% of words.** Rule matching catches the obvious cases
and misses abstract vocabulary, which is fine for building practice decks — every
category has 12–68 words in it — but it isn't complete. The two ways forward are
adding seeds by hand, or batching the untagged words through an LLM once and
pasting the result in as extra seeds. The build script doesn't care which.

## Structure

```
scripts/build_data.py     data pipeline (run once, or after editing categories)
scripts/categories.json   category rules
src/lib/data.js           loading + filtering
src/lib/srs.js            spaced repetition
src/lib/tts.js            Web Speech wrapper
src/lib/pb.js             PocketBase client + ID generation
src/lib/progress.svelte.js  reactive progress store, local + synced
src/routes/               home, vocab, sentence, account
pocketbase/SETUP.md       collections, API rules, backups
```

## Spaced repetition

`src/lib/srs.js` is an SM-2 variant with three ratings mapped to the three
buttons: *Don't know* (again), *Do again* (hard), *Know it* (good). Card state is
`{ease, interval, due, reps, lapses, seen}`, which is small and JSON-safe so it
syncs as a single blob.

The rest of the app only calls `newCard`, `review`, `isDue` and `sortByPriority`,
so swapping in `ts-fsrs` later means replacing one file.

## Audio

Client-side Web Speech, as requested. `src/lib/tts.js` picks a `zh-CN` voice,
preferring a locally installed one so it keeps working offline.

Be aware of what this costs you: Android devices without the Google Chinese
language pack have no voice at all, some Windows voices are network-backed and
go silent offline, and tone sandhi (你好 → *níhǎo*) is handled inconsistently
across engines. The Account tab shows which voice was found and has a test
button. If quality becomes a problem, pre-generate MP3s at build time and keep
this module as the fallback — `speak()` is the only call site.

## Accounts

Creating an ID generates one string like `jade-tiger-x7k2m9q4wp3n`. There is no
separate key — the PocketBase password is derived from the ID with SHA-256, so
the ID alone signs in anywhere. That means the ID *is* the credential and needs
its ~62 bits of randomness; don't shorten the tail.

There is no recovery. That's inherent to having no signup — see the note at the
bottom of `pocketbase/SETUP.md`. The Account tab also has JSON export/import so
progress isn't trapped.

## Styling

All of it lives in `src/app.css`. The top block is tunables — colours, spacing,
border weights, and per-element type sizes like `--flash-zh` and
`--flash-zh-weight`. Components carry class names only; the sole inline styles
left are the computed widths on progress bars.

Sentence pinyin comes from pypinyin at build time. It does not apply tone sandhi
(不 stays `bù` before a fourth tone) and occasionally gives a full tone where a
native speaker uses the neutral one (`yī fú` rather than `yī fu`). Fine as a
reading aid, not authoritative.

## Not done yet

- No service worker or manifest. Add `@vite-pwa/sveltekit` when you want offline
  and installability.
- No stroke order, no traditional character variants, no measure words.
- Class-only single characters (睛, 蕉, 萄) are bound morphemes. Their example
  sentences come from substring matches inside the full word (眼睛, 香蕉), which
  is correct but means the sentence never shows the character in isolation.
- 573 definitions are shared by two or more words ("happy" → 高兴, 快乐, 快活,
  美满, 舒畅, 喜悦). This makes English-first vocab cards ambiguous. Either enrich
  the definitions from CC-CEDICT, or lean on sentence context for those.
- Sentence practice isn't tracked, by design.
